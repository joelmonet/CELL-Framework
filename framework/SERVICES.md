# Reusable services (source candidate)

The independent Linux SDK build now passes its JSON, service, prepared exchange, product query, interaction, wrapper and parameter-timeline tests. Device I/O is separately exercised by an installed consumer and the Live Immersive application. These checks cover their stated contracts; they do not qualify the entire SDK, gallery, every platform or a production suite editor. Native accessibility providers and a GPU renderer remain separate work.

| API | Contract |
| --- | --- |
| `audio.hpp` / `Transport` | Separate host tempo availability and numerical fallback. Native plugin adapters preserve positive finite fractional BPM and explicitly mark missing/invalid host tempo. Runtime chunking and parameter segmentation retain the flag. See [TRANSPORT.md](TRANSPORT.md). |
| `allpass.hpp` | Fixed-capacity, inline-state all-pass cascades with bounded coefficients. Fixed coefficients preserve magnitude and change phase; callers smooth time-varying coefficients. |
| `envelope.hpp` / `ladder.hpp` | Linked adaptive envelope detection, hysteretic audio triggering, and two-substep TPT ladder low-/band-pass responses with reusable excitation for parallel filters. Preparation and settings establish time constants; processing owns no heap storage. Musical routing and preset controls stay in the product layer. |
| `degradation.hpp` | Inline-storage fractional-rate reduction, stereo two-step low-pass, TPT ladder high-pass and integrated soft/hard saturation. Aliasing in the sample-rate reducer is intentional; it does not replace a transparent resampler. Musical profiles and their recall policy stay in the product layer. |
| `delay_history.hpp` / `state_variable.hpp` | Non-owning planar/interleaved delay views with age-guarded nearest/linear/cubic reads and constant-time logical invalidation; the owner supplies exclusive storage. Two-step TPT state-variable low-/band-/high-pass responses use inline state and caller-supplied coefficients. Both public headers pass an independent C++20 consumer; musical routing, mode handoffs and storage admission remain product responsibilities. |
| `mono_reference.hpp` | Causal stereo reference selection for shared pitch/analysis clocks. Prepare the power follower and dominance hold outside processing; process one sample pair at a time. Hysteresis limits channel chatter without cancelling antiphase input or reading future samples in a host block. Inline state, no heap ownership; this does not combine or alter the audio channels. |
| `midi_message.hpp` / `smf.hpp` / `memory_stream.hpp` | Native MIDI message ownership and buffered Standard MIDI File I/O with 64-bit cumulative ticks, running status, SysEx/meta payloads, tempo and SMPTE mapping. Large immutable messages share storage; common channel events fit inline. File I/O and large-payload lifetime operations run off audio. See [MIDI-FILES.md](MIDI-FILES.md). |
| `tci.hpp` / `wave_export.hpp` | Indexed observed-v4 embedded TCI integer audio and seekable PCM24 WAVE views, sharing one source file without sample extraction. Explicit streaming WAV export also accepts GOG views, with cancellation and atomic publication. Missing final TCI scalars use documented zero fill; instrument mappings, product UI and instrument-format writing remain separate. See [TCI-FORMAT.md](TCI-FORMAT.md). |
| `midi.hpp` / `midi_tools.hpp` | Prepared bounded MIDI output buffers and an independent short-message processing engine. Transpose, key/velocity ranges, scales/chords, channel maps and CC transforms retain note ownership across live scalar changes. Shared destinations release only after their last owner. Panic, seek/stop cleanup and overflow recovery perform no heap work on audio. SysEx, UMP and timed generators are not implemented by this initial service. |
| `midi_note_state.hpp` | Audio-thread-owned MIDI 1.0 target-note state with separate ownership on all 16 channels, damper latches, velocity-zero releases and channel-scoped panic/controller reset. Queries expose physical keys, sounding keys and their pitch union. No heap or locks; process messages in sample order and call `clear()` for lifecycle reset. Retriggers replace the same channel/key owner. Sostenuto, SysEx, UMP and system reset messages are outside this service. |
| `audio_device.hpp` | Optional `Cell::AudioDevice`: enumerated native endpoints, explicit start/stop and interleaved float32 duplex callbacks. No dummy backend. Buffer estimates and callback deadline overruns are distinct from measured physical latency and hardware xruns. Device lifecycle runs off audio; stop joins the callback. PulseAudio preserves wire index order and disables server remixing. |
| `jobs.hpp` | Non-real-time, bounded worker pool with priorities, cancellation, progress and owning results. Owner generations suppress stale results. Workers do not call editors or host callbacks. |
| `read_ahead.hpp` | One fair disk/decoder worker for registered media clients. Each callback performs a bounded slice and sets its next polling delay; continuously busy clients cannot monopolize scheduling. Off-audio removal joins any active callback before reader destruction. The registry is dynamic, and the service must outlive its clients. |
| `latest_exchange.hpp` | Single producer/consumer prepared-object handoff. Unconsumed replacements coalesce on the producer, including arbitrary pre-callback registration bursts. Audio borrows raw pointers and retires old objects through a bounded queue; allocation, superseded-object destruction and reclamation stay on the producer. This complements the generation/cancellation and crossfade contracts in `PreparedExchange`. |
| `history.hpp` | Immutable 64 KiB pages, collision-checked deduplication, sharing of resource payloads, bounded timelines and acknowledged undo. The budget accounts retained payload/page references; it is not a bound on total process RSS. |
| `state_transfer.hpp` | Immutable processor snapshots, two bounded leases per server, 192 KiB chunks, 30-second expiry and accidental-corruption detection. It is not authenticated network transport. |
| `operation_ack.hpp` | Owning command/restore requests and separate processor acceptance. Transport admission does not imply a successful state change. |
| `callback_gate.hpp` | One nonblocking audio callback entry and an optional control-thread pause for stopped-only state codecs. Audio emits silence while paused. Control waits for the current callback to finish, rejects concurrent control owners and resumes entry after a bounded timeout or completion. This service provides safe ownership, not seamless preset transitions. |
| `assets.hpp` | Worker directory scans, extension filters, deterministic sorting, limits, search, tags and favorites. Annotation persistence is explicit. |
| `thumbnails.hpp` | Shared bounded LRU waveform cache; weighted min/max/RMS pyramids. Default decoding supports RIFF/WAV; other readers are injectable. This service does not play audio. |
| `files.hpp` | Bounded reads, atomic replacement and streaming output. Uncommitted output removes its owned temporary file and preserves the previous destination. |
| `state_tree.hpp` / `xml.hpp` / `byte_block.hpp` / `result.hpp` | Native control-thread project state, exact 64-bit scalar identities, shared immutable binary payloads, iterative project XML and legacy host-envelope compatibility. Default project admission derives from the input size. Details and qualification scope are in [PROJECT-STATE.md](PROJECT-STATE.md). |
| `json.hpp` | Owning bounded JSON, finite double values, strict syntax/UTF-8/surrogates, duplicate-key rejection and deterministic writing. Parsing/writing is non-real-time; input, text, node and nesting budgets are explicit. Integer identities beyond exact double range use strings. |
| `ui_components.hpp` / `ui_values.hpp` | Reference-free controls, physical-unit parsing, mouse/touch geometry, centered text and stable control identities independent of host parameter IDs. |
| `ui.hpp` image decoding | Worker-safe bounded decoding through the installed renderer; optional display-size Lanczos scaling before publication. |

`examples/control_gallery` consumes these independent interfaces without a product UI reference. Its analytical/character styles, pointer/touch sizing, knob/fader faces, focus, typed values and accessibility actions are source exercises. Rendering and native interaction tests remain unrun.

Audio callbacks must not call file, history, browser, image, job submission or state-transfer APIs. Prepare parameter bindings outside processing, then read the bound atomics in the callback. Shared pools/caches are shared within the same loaded runtime, not guaranteed across separately linked plugin binaries. A cache client may retain values outside a cache's own eviction budget.

The original Cell framework is Apache-2.0; product code remains commercial. The current root license and third-party notices continue to apply. Studio's optional product services are excluded from the independent SDK package.

## Retained DSP transitions

`PreparedExchange` now has optional `audioUpdateRetainingPrevious()`, `audioPrevious()` and `audioReleasePrevious()` operations. The audio consumer can advance both mutable DSP objects during a crossfade. Further replacements stay queued while the previous borrow is held; only the non-audio producer reclaims a released object. Callers must end all uses of the old borrow before releasing it, and handle retirement backpressure. Existing ordinary handoffs keep their earlier behavior. The ownership/cancellation/backpressure/concurrency fixtures now pass in the Linux suite QA run. The first source consumer is the suite SPACE IR service; native lifetime, sound and performance qualification remains pending. The core license decision is unchanged.

The suite QA run also compiles the independent stage-specific oversampler and passes its DC, latency, passband, alias-rejection, partition and allocation regressions. The original-code matrix and exact scope are in [the Linux suite checkpoint](../docs/SUITE-LINUX-QA.md). These selected tests do not qualify every SDK service or platform.
